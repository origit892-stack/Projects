# Leads Console — approval loop (built 2026-11-08, user asleep mandate)
The "I approve in chat, you check every 3 hours and act" machine.

## Flow
1. **Radar (cron, 09:00 IST, daily)** finds new posted requests → drafts replies → appends to `QUEUE.md` AND `STATE.json` (leads, status `new`) → re-renders the page → Hebrew digest to the user.
2. **Dashboard** — `https://origit892-stack.github.io/agent-operator/leads.html` (GitHub Pages, dark theme, auto-refresh 5 min). Shows each lead: id, fit, status badge, source link, draft. Non-sensitive (no personal data of leads beyond the public post link).
3. **User approves in chat**: "approve L-001" / "reject L-001" → the chief sets `status` = `approved`/`rejected` in STATE.json, re-renders, pushes, replies with confirmation.
4. **3-hour check (cron `30 1,4,7,10,13,16,19,22 * * *`)** — compares STATE.json vs the last snapshot (`.last_check.json`):
   - no change → silent (no output).
   - `approved` → send the approval reply (site link + payment link from config IF set; if not → `awaiting_payment` + one-line notice to user).
   - `rejected` → send the short polite rejection.
   - After acting: status → `sent_approval`/`sent_rejection`, snapshot saved, page re-rendered, push, Hebrew one-liner per lead.
5. **User confirms payment** ("L-001 paid") → `paid` → work starts as a normal project (console marks `started`).

## Send channels (auto-send is ONLY possible where the agent can actually send)
- **NONE wired yet** (2026-11-08: no himalaya/email, no telegram bot token, no reddit/x sessions).
- Therefore until a channel exists, acted leads go to `awaiting_channel` with the ready-to-send message in `notes` — the user pastes+sends (30s) or wires a channel:
  - **Telegram bot** (user does @BotFather, 2 min) → best for site leads (site already links the bot).
  - **Email** (himalaya + user's SMTP) → leads whose post includes an email.
  - Board replies (Reddit/X) → user's own accounts, user-sent, always.
- When a channel appears: set `config.send_channels` in STATE.json; the 3-hour check starts auto-sending for matching leads.

## Files
- `STATE.json` — the single source of truth (config + leads). Lead: {id, created, source, fit, title, draft, status, updated, notes}.
- `render.py` — STATE.json → `/Users/Ori/Documents/agent-operator/leads.html` (run: `python3 render.py`; then commit+push the agent-operator repo).
- `QUEUE.md` — human-readable radar output (kept for the archive/history).
- `.last_check.json` — snapshot hash for the 3-hour check (generated by the check itself). Hash method (use exactly this so runs compare consistently): `sha256(json.dumps(leads, sort_keys=True, ensure_ascii=False).encode())` over the `leads` array from STATE.json.

## Status machine
`new` → (user: approve) `approved` → (check: sent / no channel) `sent_approval` | `awaiting_channel` | `awaiting_payment` → (user: paid) `paid` → (work) `started`
`new` → (user: reject) `rejected` → (check) `sent_rejection` | `awaiting_channel`
`dead` = closed without action (stale >30d or user said drop).

# Lumio 3.3 — שדרוג ללא שינוי העיצוב הקיים

## מה חדש
- משימות מכל המקורות: סינון לפי מערכת, מקצוע, סטטוס ותאריך; מיון לפי דחיפות; תיאור; מקור וקישור.
- כפילויות בין מערכות מאוחדות **בתצוגה בלבד** לפי כותרת מנורמלת, מקצוע ויום הגשה (עלולות להיות טעויות בזיהוי; המקורות נשמרים בנפרד).
- מסך **לימודים**: מבחנים, ציונים, הודעות ומערכת שעות יומית/שבועית לפי ימים, כולל ביטולים ושינויים.
- כרטיסי מבחנים, ציונים ועדכונים במסך הבית.
- נתוני לימודים נוספים נשמרים ב־Supabase עם RLS אישי.
- אין נתוני דוגמה או טענה שספקים מסונכרנים ללא בדיקה.

## שדרוג Supabase — פעולה אחת חובה
לאחר גיבוי הנתונים, הרץ ב־Supabase SQL Editor את `database-upgrade.sql` **פעם אחת**. הוא מוסיף את `school_items` עם RLS ואינו משנה טבלאות `tasks`, `profiles`, `connections`.

## הפעלה
`npm run dev` ופתח `http://localhost:5173`. הפורט תפוס? `PORT=5174 npm run dev`.
לבדיקות: `npm test`.

## מה עובד ומה עדיין דורש הרשאה
- **Supabase**: חשבונות, משימות ומידע חדש (אחרי SQL). התלמיד צריך להתחבר לחשבון לומיו.
- **Google Classroom**: המחבר הקיים פועל רק כאשר מוגדר OAuth Client ID וכשמשתמש נתן הרשאת Classroom. זה אינו חיבור אוטומטי בהזדהות משרד החינוך.
- **משו״ב / אופק / פטל**: פתיחת האתר וייבוא; לא אומת API מורשה עם SSO.
- **שחף**: מקור מערכת שעות פתוח/ייצוא אם בית הספר מספק, אחרת ייבוא.
- אין שמירת סיסמאות משרד החינוך או עקיפה של שירות ההזדהות. אין מפתחות שרת בדפדפן.

## ייבוא מידע לימודי נוסף
מסך 'לימודים' מאפשר להזין פריט או לייבא JSON. לדוגמה **מבנה בלבד, לא נתוני תלמיד אמיתיים**:

```json
{"items":[{"kind":"exam","source":"manual","title":"שם מבחן","subject":"מקצוע","event_date":"2026-12-01"},{"kind":"grade","source":"manual","title":"שם מבחן","score":90,"event_date":"2026-12-02"},{"kind":"timetable","source":"manual","title":"שם שיעור","day_of_week":0,"start_time":"08:00","change_type":"normal"}]}
```

`kind`: `exam`, `grade`, `announcement`, `timetable`. הפריטים מוצגים כמידע שהמשתמש הזין/ייבא, ולא כמידע שאומת מול הספק.

## בטיחות
כל תלמיד יכול לראות רק נתונים עם `user_id` שלו באמצעות RLS. יש לבדוק עם שני משתמשי בדיקה וגם את RLS של הטבלה החדשה. `config.mjs` מכיל מפתח ציבורי בלבד; לעולם אל תשים בו מפתח סודי. הקפד לקבל הסכמה מתאימה לפני שימוש עם קטינים.

# לומיו 2.0 — אתר + אפליקציה לטלפון + חשבונות + מסד נתונים

## מה באמת עובד

- יצירת חשבון באמצעות אימייל וסיסמה ב-Supabase Auth; אימות אימייל בהתאם להגדרות הפרויקט.
- שמירת פרופיל אישי: בית ספר, עיר, שכבה, כיתה (ברירת מחדל: קציר ב׳, רחובות, ט׳5).
- שמירת מטלות בענן ב-PostgreSQL, עם Row Level Security לכל משתמש.
- משימות, לוח 14 ימים, סימון ביצוע, הוספה, מחיקה, ייבוא/ייצוא קובצי JSON.
- כניסה ל-Google Classroom בעזרת OAuth ושימוש ב-API הרשמי לקריאת קורסים, מטלות והגשות של התלמיד, לאחר הגדרת Client ID ואישורי Google.
- תוסף Chrome ניסיוני לקריאת טקסט משימות **גלוי בלבד** מהעמוד הפתוח והפקת קובץ לייבוא, עם תצוגה ועריכה לפני הייבוא.
- PWA להתקנה במסך הבית דרך אתר HTTPS.

## מה עדיין אינו מחובר

משו״ב, אופק, פטל ושחף **אינם** מסונכרנים ברקע עם משרד החינוך. קישור לאתר אינו מעניק API. תוסף הייבוא אינו מבטיח זיהוי אוטומטי נכון של מטלות בכל אתר, ואינו ניגש לסשנים, עוגיות, סיסמאות או ממשקים פרטיים. תוסף Chrome מיועד למחשב בלבד. שירותי Moodle של פטל תלויים בהרשאת מפעיל האתר. שחף דורשת מקור נתונים ציבורי או מורשה. לא נכלל WhatsApp.

## הגדרת פרויקט Supabase — כבר בוצעה בקוד

הקובץ `config.mjs` מכיל את כתובת הפרויקט ואת המפתח **הציבורי** שסיפק מנהל לומיו. אין לתלמידים שום צורך להקליד כתובות שרת או מפתחות. תלמיד נכנס רק עם האימייל והסיסמה האישיים שלו. אל תוסיף לקובץ מפתחות `sb_secret_` או `service_role`.

### 1. יצירת הטבלאות — חובה לבצע פעם אחת

1. היכנס לפרויקט שלך ב־https://supabase.com/dashboard.
2. עבור אל SQL Editor, הדבק את הקובץ `database.sql` והרץ אותו. הוא יוצר טבלאות עם Row Level Security כך שלכל תלמיד יש נתונים פרטיים.
3. ב־Authentication -> Providers -> Email ודא שהרשמה במייל פעילה. אם נדרש אימות כתובת מייל, התלמידים יצטרכו לאשר הודעה.
4. ב־Authentication -> URL Configuration, הגדר Site URL לדומיין שבו תפרסם את האתר.

### 2. הפעל את לומיו

דרוש Node.js 18+ (ללא npm install):

```bash
cd lumio-v2
npm run dev
```

פתח `http://localhost:5173`, צור חשבון Lumio. כל תלמיד שיירשם משתמש באותו פרויקט Supabase, אבל המידע נשמר בנפרד לפי מזהה המשתמש שלו.

**שים לב:** כתובת ומפתח הוגדרו בצד הלקוח, אך זה לא מפעיל בעצמו את טבלאות SQL, הגדרות Auth, או שירות פריסה ציבורי. אין לפרסם לתלמידים לפני בדיקת RLS ואימות מייל.

### 3. חבר Google Classroom (אופציונלי אך מומלץ)

1. פתח https://console.cloud.google.com/ וצור פרויקט.
2. הפעל **Google Classroom API**.
3. Google Auth Platform -> Branding, Audience, Data Access: הגדר OAuth consent screen; הוסף משתמשי בדיקה לפי הצורך. אם תלמידים מתחת לגיל 18, מנהל Google Workspace for Education עשוי לחסום אפליקציה שאינה מאושרת.
4. צור OAuth Client מסוג **Web application**. הוסף ב-Authorized JavaScript origins את `http://localhost:5173` ואת דומיין ה-HTTPS שלך. אין צורך ב-client secret בדפדפן.
5. הכנס את **OAuth Client ID** לשדה `google` בקובץ `config.mjs` ובצע פריסה מחדש. אל תכלול Client Secret בדפדפן.
6. בחיבורים -> "חבר Google" -> אשר `classroom.courses.readonly` ו-`classroom.coursework.me.readonly` -> יוצגו הקורסים והמטלות הזמינים בהרשאת התלמיד. התחבר מחדש בעת פקיעת תוקף ההרשאה; אסימון Google נשמר **בזיכרון בלבד** ולא ב-DB.

> Supabase משמש לחשבון לומיו, ואילו Google OAuth משמש לקריאת Classroom — אלו שני תהליכים נפרדים. אין גישה לסיסמת משרד החינוך.

### 4. ייבוא ממשו״ב / אופק / פטל / שחף (מחשב)

1. Chrome -> `chrome://extensions` -> Developer mode -> Load unpacked -> בחר תיקיית `extension`.
2. פתח את עמוד המשימות באתר המקור והתחבר בעצמך בדרך הרשמית, כולל הזדהות משרד החינוך אם האתר מציע אותה.
3. לחץ על תוסף "Lumio Reader", בחר מערכת ולחץ "חיפוש משימות בעמוד הפתוח".
4. בדוק את הפריטים: התוסף עלול לזהות גם טקסט שאינו משימה. ערוך/מחק פריטים, ואז ייצא JSON.
5. בלומיו -> חיבורים -> "ייבוא JSON ממערכת לימוד" -> בחר בקובץ. המשימות יישמרו ב-DB האישי שלך ויופיעו גם בטלפון.

## התקנה בטלפון

פרוס את **כל** קובצי הפרויקט בשרת סטטי התומך HTTPS (למשל Cloudflare Pages, Netlify, Vercel static; אין צורך ב-build). ב-Supabase עדכן את Auth Site URL. ב-Chrome/Android לחץ "הוספה למסך הבית" או "התקנת אפליקציה"; ב-Safari/iPhone בחר "הוסף למסך הבית". שים לב: `npm run dev` נועד למחשב המקומי, ואינו חושף את האתר לטלפון באינטרנט.

## פרטיות והפצה

- בדוק שהטבלאות מבודדות בין תלמידים לפני פריסה ציבורית. יש RLS ולכל רשומה `user_id`.
- חשבונות קטינים: לפני השקה בית-ספרית נדרשת בחינה מתאימה של פרטיות, הסכמות ואבטחה; אין לאסוף מספרי זהות וסיסמאות משרד החינוך.
- Publishable/anon key רשאי להיות גלוי; Supabase secret / service_role לעולם לא.
- נתוני משימות שנצפו באתר מקור מיובאים רק ביוזמת המשתמש.
- אין הבטחה לסנכרון רקע כשמחשב כבוי או כשהדפדפן סגור.

## בדיקות

`npm test` — בדיקות יחידה לייבוא, מיזוג, תאריכים ובטיחות כתובות. בדיקת DB / OAuth אמיתית מחייבת מפתחות וחשבונות בדיקה של המשתמש ולא בוצעה מראש.

## תוספות גרסה 3.1

- חיבורים: ייבוא קובצי `.ics` (יומן), `.csv` (טבלאות) ו־`.json` ישירות גם מאנדרואיד ומאייפון.
- במסך חיבורים בוחרים את מקור הקובץ לפני הייבוא; הנתונים נשמרים ב־Supabase באמצעות מדיניות RLS הקיימת.
- Google Calendar מאפשר לייצא ICS ממחשב אם בית הספר אינו חוסם ייצוא. אירועים עם מועדי הגשה עשויים לכלול מטלות Classroom; לא כל מטלה תופיע.
- ממצאים, מגבלות וסיכוני אבטחה: `INTEGRATIONS.md`.
- לא נדרש SQL חדש לשדרוג הזה; הנתונים נשמרים בטבלת tasks שכבר נבדקה.


## לומיו 3.2 — העברה ישירה מהדפדפן (מחשב)

1. Chrome → `chrome://extensions` → Developer mode → Load unpacked → בחר `extension`.
2. היכנס למשו״ב, אופק או פטל **באתר המקורי**, כרגיל, ופתח את רשימת המשימות שלך.
3. לחץ על תוסף Lumio Reader, בחר מקור, לחץ ״חיפוש משימות״, בדוק ותקן את הפריטים.
4. הקלד פעם אחת כתובת לומיו (`http://localhost:5173` בפיתוח או כתובת HTTPS שלך) ולחץ ״העבר את המשימות ללומיו״.
5. לומיו תבקש אישור מפורש ותשמור את הפריטים בחשבון Supabase שלך. לאחר מכן הם יופיעו גם בטלפון.

העברה זו אינה סנכרון רקע: יש לחזור על סריקה כשיש שינויים באתר המקור. התוסף אינו יכול לקרוא אפליקציות Android/iOS.
החיבור הישיר ל־Classroom API דורש OAuth Client של Google; אי אפשר להפעילו ללא הגדרה כזאת.
הפעלת API של פטל או נתוני שחף עדיין תלויה בגישה שמעניק הספק/בית הספר.

### פרטיות

לומיו Reader קורא טקסט גלוי **רק אחרי לחיצת משתמש**. העברת הפריטים מתבצעת בקטע ה־URL שלא נשלח לשרת בעת ניווט; לומיו מסירה אותו מיד משורת הכתובת ומבקשת אישור לפני שמירה. אל תבחר משימות של תלמידים אחרים או טקסט המכיל פרטים רגישים.
